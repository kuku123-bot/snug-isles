# Snug Isles — dev notes (architecture + decisions)

Cozy 2-player co-op island crafting/building game. Browser (Canvas2D + DOM UI), iPad 11 + MacBook M4.
Original art/audio (all procedural). NOT affiliated with, and uses no assets from, Forager.

## Hard rules
- No third-party game assets. All sprites are generated in code (`js/gfx`), all audio is WebAudio synth.
- Pure modules (no DOM): `js/util.js`, `js/data/*`, `js/sim/*`, `js/gfx/pixmap.js`, `js/net/protocol.js` -> testable in Node.
- Host-authoritative multiplayer. Client moves its own player locally (client-authoritative position),
  everything else (inventory, world, mobs, drops, crafting) is host-side; client mirrors via events+snapshots.
- Worldgen runs ONLY on the host; client receives ground data in snapshot / `land` events (no cross-engine determinism needed).
- Structures/blueprints are NOT items: they are built from the Build menu using materials (Forager style).
- Never commit secrets. Repo is public (GitHub Pages free tier). Commits use the GitHub noreply email.

## Rendering
- Low-res canvas in "art pixels" (TILE = 16). Integer scale `s` = round(deviceHeight / 280). CSS upscales w/ `image-rendering: pixelated`.
- DOM for UI (crisp text, easy touch). Icons come from the sprite atlas via CSS background-position.
- Walls: "face + thin cap" style (16x20 sprite: 4px cap above footprint, 16px face). Windows/doors anywhere. Autotile by N/E/W.
- Floors: flat 16x16. Furniture/things: upright sprites, bottom-aligned to footprint, y-sorted by footprint bottom.

## World
- Lands are 20x20 tile squares in a grid (default 9x9). Start land in the middle. Buy adjacent lands with shared coins.
- Biomes: meadow, desert, tundra, swamp, graveyard, volcano, crystal, void.
- Layers (typed arrays): ground, floor, wall, wallState, occ(thing id). Things in a Map (resources, stations, furniture).

## Progression
- Per-player: inventory, XP/level, skill tree (points per level), hp/hunger/energy.
- Shared: coins, tech tree (research at Research Table), lands, world time, chests.
- Tiers 0..8: wood/stone -> copper -> iron -> gold -> swamp/graveyard magic -> volcano obsidian -> crystal -> void/star.

## Networking
- PeerJS cloud signaling (WebRTC datachannel, JSON strings, own chunking) + manual copy/paste signaling fallback.
- Host sends: events (reliable, batched), snapshots (mobs/drops/players ~15Hz), private player state.
- Client sends: pos (~25Hz), commands.
- Either player can host: client keeps a backup copy of the world.

## Things that were learned the hard way (keep these in mind)
- **Networking**: free public TURN relays are dead (the old "openrelay" one included). The ICE list contains only STUN servers that were probed live; connections are direct P2P. `?turn=…` adds a relay on one device. Tested: cloud PeerJS + local PeerServer + manual copy/paste, Chromium<->WebKit, reconnect, backup copy.
- **Manual pairing**: the host's wait only starts when the answer is pasted (humans take minutes); the panel keeps its `<details>`/textareas across re-renders (it used to be rebuilt on every status change).
- **Backup relay** (`net/mqtt.js`, `net/relay.js`, `net/relaykey.js`): public MQTT brokers over WSS as a dumb pipe. Measured: HiveMQ delivers 100% up to 80 msg/s, EMQX drops 30-70% above ~15/s, Mosquitto's test server is sometimes down; so HiveMQ goes first, the others join after a stagger, relay links run at about half the message rate (`conn.lowRate`). Messages are AES-GCM sealed (`role|gid|seq|text`, key from an 80-bit code, topics from a hash of it), numbered per direction, duplicates dropped, short reordering tolerated, a persistent gap closes the link so the app reconnects (fresh snapshot). The guest repeats everything on each relay it can reach until the host answers, then pins to the answering one; the host answers on every relay it recently heard that guest on. Direct WebRTC is always tried first. The developer's own network showed symmetric NAT (two STUN servers gave different mapped ports), which is exactly why this exists.
- **Join approval**: `HostLink` asks the host before admitting a pid that is not in `world.players` (room codes are 5 chars). The card lives in `#joinreqs` above every panel. A returning partner on a new device can claim an offline character (`adopt` + `prk` event). `PROTOCOL` bumps on any wire change; `BUILD_ID` (source hash, injected by tools/build.mjs) only produces a soft "different versions" warning.
- **Goals** (`data/goals.js`, `sim/goals.js`): the host evaluates conditions on a census every 1.5s; counters live in `shared.flags.gs` (host only, persisted), the done-list in `shared.flags.goals` (replicated by `goal`/`goals` events + snapshot). Item goals use `made_<item>` counters (crafted/smelted/produced), never inventory contents (the starting kit would complete them).
- **Spawning**: lands are 20x20 so the old 14-23 tile spawn ring never fit the starting island; `spawnTick` falls back to a closer ring and scales the early crowd. New worlds have `flags.age` (played seconds): peaceful for 120s, ramping to full over 240s.
- **Pets** (`sim/pets.js`): `p.pet` (saved in `serializePlayer`, which is a field whitelist: new player fields must be added there!) + a follower mob with `m.pet = pid` handled by `petAI` in combat.js; `ensurePets` re-creates it every ~1.5s; pets are excluded from spawn caps. The Old Key is consumed by `openWildChest` for a second loot roll.
- **Refunds** equal what building costs *now* (`buildMult`), otherwise discounts could be farmed by build/remove cycles.
- **Presets** must only use values that exist in `OPTIONS` or `sanitizeSettings` silently resets them (tests/content.test.js checks).
- **Touch**: while building, the joystick zone shrinks to a corner (`.joyzone.compact`) so the rest of the screen paints; quick taps count (pointerdown+up inside one frame); furniture is placed on finger-lift so you can slide the ghost. Wake lock is re-requested on `visibilitychange`.
- **Short windows** (iPad Safari with toolbars ~1180x700): menus use `100vh`-based heights and a `max-height: 740px` media query.
- **Smooth look** (`render/smooth.js`, `gfx/smooth.js`, `render/labels.js`, `gfx/style.js`): the game still draws into the low-res art canvas; a WebGL2 presenter lays a device-resolution canvas over it and runs a "vote" upscaler (each nearby art pixel votes for its colour with a gaussian weight, margin = anti-aliasing) so staircases become slopes and blobs round. `gfx/smooth.js` is the CPU reference; `tests/smooth.test.js` pins its behaviour and `tools/e2e-smooth.mjs` checks the GPU output against it pixel by pixel (worst error 1/255). Lessons: (1) a per-pixel colour bias keeps detail but stops shapes rounding, so thin things are protected *adaptively* (a pixel's colour must win at its own centre by `MIN_CENTRE_MARGIN`) and thick shapes get no bias; (2) edge width must come from the local vote gradient, a fixed width fades dots and lines at low zoom; (3) a GPU speed check must take the *fastest of several runs* (queued compositor work inflates one run) and only on real frames; slow GPUs first draw at 75%/55% of the pixels (`Presenter.rs`), then fall back to the pixel look; (4) headless Chromium renders WebGL in software (SwiftShader), so the presenter refuses software renderers unless `?force=1`: the old e2e suites keep exercising the pixel path, `e2e-smooth.mjs` forces the shader; (5) the 2D art canvas is never hidden (the GL canvas just covers it), so pointer coordinates, fallbacks and context loss are free. In-world text (name tags, numbers, prices) is drawn by `TextLayer` with the round UI font at full resolution; the UI font is Fredoka (`:root[data-look=pixel]` brings back Pixelify). Art knobs (soft outlines, ground noise, no dithering) live in `gfx/style.js`.

- **Trees** (`ui/treedata.js` pure box-building, `ui/treelayout.js` layout, `ui/tree.js` DOM, `ui/panels/tech.js` the two panels): one branch per page, big square picture buttons, lines run left to right. Research columns = how far along the *whole* tech chain a tech is (`techDepth`, so every line goes left to right even when a prerequisite lives in another branch; those show as little pictures on the box); skills are real trees (each `req` is inside its own branch: a test enforces it). Layered layout puts a box level with the average of its parents; skills use a tidy tree. Technologies and skills share one effect vocabulary (`calcStats` sums `skillFx + techFx` per key): adding a tech bonus is `fx: { key: amount }` plus a line in `STAT` of tests/trees.test.js; a test proves every promised bonus really moves its stat. New pieces: styles are palette-only (`STYLE_PAL`), walls are a face colour (`plasterFace`), floors/wall decor/decor are small sprite functions; wall/floor codes are remapped by id on load, so new pieces can go anywhere in the lists.

- **Building preview + turning** (`js/game/builder.js`, `data/facing.js`, `gfx/art/turns.js`, `Renderer._drawBuildGhost`): `rot` 0..3 (down/right/up/left) is stored on things (`['ta', …, rot]` event, saves append `t.rot || 0`; old saves load unturned). `facing.js` says which pieces turn (every furniture design that looks different from the side + bench + picnic table: 74 pieces), what each view is and how the footprint swaps; sprites of turns 1-3 are `t_<id>_r<rot>` (`registerTurns`, drawn from the same palette code as the front view; `expectedSprites` and tests/facing.test.js make sure every one exists and is as wide as its footprint). Pieces that cannot turn still flip (mirror); a turned piece is never also mirrored. Controls: R / Shift+R / mouse wheel in build mode / the Rotate button. **Lesson:** the ghost was never drawn for a long time because the renderer read `g.build` while the Builder lives at `g.builder`; tools/e2e.mjs now compares pixels with the ghost on and off. On touch the ghost follows a finger while it is down and otherwise rests in front of the player (Place and Rotate buttons work from there); furniture is still placed on finger-lift.
- **Using furniture** (`sim/furniture.js`, pure): beds are SOLID and used to put the player *inside* them, and `World.moveBox` rejects every step while the box overlaps something solid, so after sleeping you could not move at all. Now: seats have one slot per cushion (`seatSlots`, `p.sit = {id, i}`, facing = the piece's turn), a sleeper's head lies on the pillow (`bedSpot`/`pillowAt`), and getting up steps you out to the first free tile beside the piece (`exitSpot`: the side it faces first, then the sides, then behind, ring 1 then 2, then `nearestStand`). The exit depends only on the piece and the seat, never on where the player currently is, so the player's own screen can step out the instant a key is pressed and the host computes the same spot; the `wake` command therefore does not move anybody (otherwise a fast walker gets pulled back by the late teleport). `p.bed` (host only, not saved) is the id a sleeper lies in; screens that do not know it (a partner's) find the piece by position (`furnitureUnder`). `updateLocalPlayer` also un-sticks the local player every frame (`unstickSpot`), which repairs old saves that were saved inside a bed. Lying down works at any time of day (only a night skips); the cozy score of a sleeper is computed from the tile they would step out onto (it read 0 from inside the solid bed, so nobody ever woke up cozy). Drawing: sleepers are drawn right after the bed with `playerSleepHead` turned to the bed's head end (two share a pillow side by side), back-facing sitters are drawn *before* the seat so its back covers their legs, front/side sitters are drawn after it and the bottom `SEAT_LIP` rows of the seat are drawn again over them; `SIT_DY` tunes the poses.
- **Dragging items** (`ui/drag.js`): one set of capture-phase listeners for the whole page, because panels rebuild their slots constantly. Any `.slot` with `data-ref='{"k":"p","i":3}'` (`k`: p bag/hotbar, e wearing, t chest slot, m machine slot) is both draggable and a drop target; a press that does not move 5px (mouse) / 9px (finger) stays a tap, and the click after a drag is swallowed for 150 ms. The picture rides 40px above a finger and a drop lands where the picture is. `canDrop` mirrors the simulation's slot rules only as a hint (tests/drag.test.js proves they agree for wearing, charms, food-only chests and machines); the move itself is the usual `{ c: 'inv', op: 'move' }` (empty slot moves, same item merges, different item swaps). `.slot[data-ref] { touch-action: none }` so a finger on a slot never scrolls a window; the HUD hotbar slots carry refs too. The bag shows its first row as the Hotbar.
- **Wild critters, clearing, storage**: critters (bunny, chick, duck, penguin, lizard…) can be hunted but only when the aim is within `r + 12` of them (`canHit`; a sword swing at the ground next to a bunny does nothing), hurt critters panic and run, pets (`m.pet`) can never be hurt; the Remove tool also clears berry bushes, opened chests and stumps (`clearableNode`/`clearNode`). Stacks hold 9999 (`STACK`, potions and trophies 999); the Pack Mule skill adds bag slots and Warehouse Keeper adds `chestSlots` to every chest (`storageBonus` = the best of all players, `growStorage` only ever grows an inventory, and replicates through `patchThing`).

- **Paint colors** (`data/paint.js` format, `gfx/tint.js` recolor, `ui/colorpicker.js`, builder `col`/`paint`/`pick`, `commands.js` `doPaint`/`paintTarget`/`colorAt`): a color is `0x8000 | r5<<10 | g5<<5 | b5` (0 = as drawn; `normColor` rejects everything else, so network/save junk is "not painted"). Tile layers carry `floorCol`/`wallCol`/`decoCol` (Uint16Array beside `floor`/`wall`/`deco`), things carry `t.col`. They travel inside the existing events (`f`/`w`/`d` get a trailing color, `ta` a trailing color, `tu` patches `{col}`); saves add a trailing `col` to thing rows plus sparse `floorCol`/`wallCol`/`decoCol` lists that are only written when something is painted. `setWall` etc. keep the color when the same piece stays (opening a door) and clear it when the piece goes. The renderer asks for each (sprite, color) once (`Renderer._painted`) and keeps it as a dynamic atlas sprite; `tintPixmap` gives every pixel its lightness relative to the whole piece around the chosen color (average pixel = exactly the color). The brush (`paint` command, V key) is free, reach/ownership checked like Remove; target order thing > wall > (decoration once the wall already has the color) > floor. The picker is a panel in `hud.buildSide` (beside the world, never over the place being built) with its own pointer-driven sliders (native range inputs are unreliable under `touch-action: none`). Drag strokes interpolate tiles (`lineTiles`) so a fast sweep cannot skip any.
- **Updates must never touch a world** (read before every release): saves are IndexedDB `worlds`/`meta` (`DB_VER` 1, never change it casually) holding `serializeWorld` JSON with `SAVE_VERSION` 1. Changes to the save format must be *additive* (extra trailing array items / extra optional keys, readers default them), and `SAVE_VERSION` stays 1 so the previous version can still open a world the newer one saved (rollback stays possible). `SAVE_EPOCH` (serialize.js) is the generation: the first time a game with a higher epoch opens a world stamped with a lower one, `App.keepCopyBeforeUpdate` stores the world exactly as it was as "<name> (before the update)" in the world list (once; copies are never copied). Bump it when an update changes how worlds are handled. `PROTOCOL` bumps on any wire change (a page of the old version is then told to reload instead of half-working). Check: `node tools/compat.mjs <git ref of the live version>` builds a rich world with that version's own code and proves the new code loads it unchanged, plays on, and that the old code opens what the new one saves; `node tools/e2e-upgrade.mjs <ref>` does the same in a real browser (old build creates the world, the new build opens it from the same IndexedDB).

## Test map
- `npm test`: sim, rules (one test per world option), content (reference integrity + reachability fixpoint of every item/tech/blueprint/recipe), playthrough (craft every recipe, build+remove every blueprint, research the tree, machines, altars…), serialize/backup, net loopback (join/approval/replication/goals), furniture (sit/sleep/getting up/cozy), facing (turned pieces), paint (colors, recolor, brush, saves, events, update copies), drag (slot hints vs the simulation), storage, clearing, critters.
- Browser: tools/e2e.mjs (mouse/keyboard), e2e-touch.mjs (real CDP touch incl. two thumbs), e2e-mp.mjs (two browsers), e2e-manual.mjs, perf.mjs (CPU-throttled stress scene), e2e-trees.mjs (Research + Skills trees on touch and mouse, three window shapes), e2e-smooth.mjs (the smooth look: shader vs CPU reference, photo, settings, context loss, slow-GPU fallback), screens.mjs, live.mjs (deployed site).
